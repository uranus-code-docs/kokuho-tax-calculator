# 設計書: 国保税試算アプリ

市区町村ごとの国民健康保険税を、確定申告前に概算するアプリ。
現在の対応は群馬県の全35市町村（令和8年度）。全市町村とも人が確認済み（`reviewed`）。計算式は自治体ごとのJSON（ルールセット）で持ち、計算エンジンは全自治体で共通にする。

この文書は、現在の実装に合わせた設計の説明。コードと食い違ったときはコードが正しいので、この文書を直すこと。

---

## 1. 設計の原則

1. **計算は純粋なTypeScript関数にする**（`app/src/engine/`）。React と DOM には依存させないので、Node 上でテストや自動検証ができる。
2. **自治体ごとの違いはJSON（ルールセット）で表す。** JSONには数値・表・選択肢だけを入れ、式の文字列やコードは入れない。
3. **JSONは必ず Zod で検証してから使う。** 型は Zod のスキーマから導出し、型とスキーマを二重に管理しない。
4. **推測した値は黙って出さない。** 市町村の資料で確認できない値（限度額など）は、県の資料や国の基準で補ったうえで、画面に注意書きを出す（13章）。ルールセットがない自治体は「準備中」にする（7章）。
5. **見た目は変えない。** 旧サイトのCSSをそのまま使う（9章）。
6. **市のExcelを正解にする。** Excelで計算した期待値と自動で照合する（8章）。

## 2. 全体構成

```
[ルールセットJSON] --Zod検証--> [計算エンジン(純TS)] --> [Reactフック(接着だけ)] --> [画面]
        ↑                              ↑
   人が作成・確認                市のExcelの計算結果（ゴールデン）で自動照合
```

| 場所 | 役割 |
|---|---|
| `app/src/schema/ruleset.schema.ts` | ルールセットの Zod スキーマ（唯一の正） |
| `app/src/data/rulesets/<年度>/<団体コード>.json` | 自治体・年度ごとのルールセット |
| `app/src/data/loadRuleset.ts` | 必要な1件だけを動的に読み込み、検証し、公開状態を判定する |
| `app/src/domain/types.ts` | 入力・結果の型 |
| `app/src/domain/formToInput.ts` | フォームの値をエンジンの入力に変換する |
| `app/src/engine/` | 計算エンジン（下表） |
| `app/src/hooks/` | `useRuleset` / `useHouseholdForm` / `useTaxCalculation`。計算ロジックは持たない |
| `app/src/components/` `app/src/pages/` | 画面 |
| `app/tests/` | エンジン・画面のテストと、ゴールデンデータ |
| `tools/oracle/` | 市のExcelから期待値（ゴールデン）を作るスクリプト（高崎市） |
| `tools/gunma/` | 群馬県の市町村のマスター、ルールセット・ページ・期待値の生成（13章） |
| `docs/gunma/` | 群馬県の市町村の調査結果とチェック結果レポート |
| `xlsx/` | 市のExcelの置き場（Excel本体はGitに含めない） |

エンジンの内訳:

| ファイル | 内容 |
|---|---|
| `engine/calculate.ts` | エントリ `calculate(rules, input)`。区分ごと・月ごとの積み上げと限度額 |
| `engine/age.ts` | 年齢区分、月ごとの被保険者判定（75歳到達で対象外）、介護の年齢範囲 |
| `engine/enrollment.ts` | 加入月・脱退月 → 12か月のマスク |
| `engine/income.ts` | 収入 → 所得（給与所得控除・公的年金等控除・併用控除）、課税標準、軽減判定所得 |
| `engine/reduction.ts` | 7割・5割・2割軽減の判定 |
| `engine/rounding.ts` | 端数処理（Excelと同じ丸めに固定） |

団体コードは総務省の全国地方公共団体コード（6桁）を使う。高崎市は `102024`。

## 3. 入力と結果（`domain/types.ts`）

### 入力 `HouseholdInput`

| 項目 | 内容 |
|---|---|
| `fiscalYear` | 年度（令和8年度 → 2026）。ルールセットの年度と違えばエラー |
| `members` | 世帯員（1〜8人。先頭が世帯主） |
| `allDeclared` | 全員が申告済みか。`false` なら所得による軽減を判定しない |
| `householdRelief` | 平等割の 1/2・1/4 軽減（特定世帯・特定継続世帯） |
| `forcedReductionRate` | 軽減率の強制指定（Excelの「強制軽減」） |

世帯員 `Member`: 続柄、生年月日、給与収入、公的年金収入、その他所得（必要経費控除後）、固定資産税額、特例軽減該当、加入月・脱退月（または12か月のマスク）。

### 結果 `CalcResult`

- 成功: 年税額の合計、区分ごとの内訳（所得割・資産割・均等割・平等割・限度額に達したか・最終額）、世帯員ごとの所得の途中経過、軽減の判定（率・判定所得・基準額）、警告。
- 失敗: `NO_INSURED`（加入者がいない。75歳以上だけの世帯など）/ `INVALID_INPUT`。
- 警告: `CAP_REACHED`（限度額に到達）、`SALARY_OVER_8_5M`（給与850万円超。所得金額調整控除は非対応）、`NOT_DECLARED`（未申告のため軽減なし）。

## 4. ルールセットJSON

実物は `app/src/data/rulesets/2026/102024.json`、スキーマは `app/src/schema/ruleset.schema.ts`。

| ブロック | 内容 |
|---|---|
| `meta` | 団体コード、自治体名、年度、`levyType`（税 `tax` / 料 `premium`）、`status`、出典URL、確認日、確認者、ページ名 `slug`、注意書き `caveats`（コード）と `notes`（文章） |
| `ageClasses` | 年齢の基準（65歳以上・未就学・18歳未満・75歳で国保から外れる） |
| `basicDeduction` | 基礎控除 |
| `income` | 給与所得控除の区間表、公的年金等控除の区間表（65歳未満・以上）、給与と年金の併用控除、特例軽減の係数 |
| `reduction` | 軽減判定（65歳以上の年金の特別控除、給与所得者等の基準、7割・5割・2割の基準額、申告が必要か） |
| `householdRelief` | 平等割の 1/2・1/4 軽減の係数 |
| `categories` | 区分（医療・後期高齢者支援金・介護・子ども子育て支援金）ごとの所得割率、資産割率、均等割（年齢による倍率つき）、平等割、限度額、限度額/12 の丸め方、対象年齢 |
| `capMode` | 限度額の判定方法。`monthly`（月ごと）のみ |

### 区間表の書き方

控除などの「収入の区間ごとに式が変わる」表は、次の形で表す。`from` 以上の最後の区間を使う。

```
値 = (round を適用した額) × rate − subtract   （0未満は0）
```

例: 給与収入 190万〜360万円は `{ "from": 1900000, "round": { "unit": 4000, "mode": "floor" }, "rate": 0.7, "subtract": 80000 }`
（= 4,000円未満を切り捨てた収入 × 0.7 − 80,000）。

### データで表せるもの・エンジンの変更が必要なもの

- **データだけで済む**: 税率・金額・限度額、軽減の基準額、控除の区間表、年齢条件、区分の追加、資産割の率。
- **エンジンの変更が必要**: 資産割以外の新しい賦課方式、自治体独自の減免、納期ごとの額の出力、月割りの端数ルールの違いなど。
  足すときは既存の自治体のJSONが壊れないようにし、`schemaVersion` を上げる場合は移行手順を残す。

## 5. 計算の流れ（`engine/calculate.ts`）

市のExcel（高崎市「国民健康保険税試算表」の計算シート）に合わせている。

1. **年齢区分**: 1月1日時点の年齢で、未就学・18歳未満・一般・65歳以上に分ける。
2. **所得**: 給与所得（区間表）、年金所得（区間表）、給与と年金の併用控除、その他所得を合計する。
3. **課税標準**: 所得 − 基礎控除（0未満は0）。
4. **月ごとの被保険者**: 4月〜翌3月の各月について、加入期間内か、生まれているか、75歳に達していないかを判定する。
5. **軽減判定**: 軽減判定所得の合計と、給与所得者等の人数から 7割・5割・2割を決める。
   対象は「世帯主」と「世帯の最初の加入月に被保険者だった人」だけ（Excelと同じ。75歳で後期高齢者へ移った人などは数えない）。
6. **区分ごとの税額（月ごと）**: その月の対象者で、所得割・資産割・均等割・平等割をそれぞれ年額の 1/12（小数第2位まで）で積み上げる。
   均等割は「年齢による倍率 × (1 − 軽減率)」を掛けてから1回だけ切り捨てる。
7. **限度額**: 月の合計が「限度額/12」を超えた月は、その額で頭打ちにする。
8. **端数**: 12か月分を合計して円に丸め、区分ごとに100円未満を切り捨てる。年税額は区分の合計。

### 限度額を月ごとに判定する理由

年度の途中で40歳・65歳・75歳になる人がいると、月によって被保険者が変わる。このとき年額で頭打ちにすると、Excelと結果がずれる。
測定では、限度額に達した231件のうち7件で、数千円〜約2.8万円の差が出た（`app/tests/cap-measure.test.ts`）。

## 6. 端数処理

- 端数処理はエンジン内で Excel と同じ方法に固定している（ルールセットでは変えられない）。`engine/rounding.ts` に集約し、ほかの場所で丸めない。
- 浮動小数点の誤差を避けるため、切り捨てには微小な値を足してから切り捨てる（`floorSafe`）。月額は1/100円単位の整数で持つ。
- 限度額/12 の丸め方（四捨五入・切り捨て）は区分ごとに違うため、ルールセットの `capMonthlyRounding` で持つ。

## 7. 公開の制御と安全な挙動

| 状況 | 挙動 |
|---|---|
| その自治体・年度のJSONがない | 「準備中」。試算は出さない |
| Zod の検証に失敗 | 「準備中」。エラーはコンソールに出し、利用者には詳細を出さない |
| `status: draft` | `VITE_ALLOW_DRAFT=false` でビルドすると表示しない（公開前の確認時だけ表示する） |
| `status: reviewed` | 試算する。画面に「参考値」と表示する |
| `status: published` | 通常どおり表示する。`verifiedAt` と `reviewer` が必須（スキーマで検査） |
| 加入者がいない | 「対象の方がいません」と表示する |
| 限度額に到達 | 画面内に表示する（`alert` は使わない） |

画面には常に免責（概算であり、実際の税額は市の通知書による）を表示する。

高崎市 令和8年度は `reviewed`（2026-11-04 確認）。群馬県のほかの34市町村も `reviewed`（2026-11-11 確認。マスターの `review` で一括して設定）。

## 8. テスト（市のExcelを正解にする）

```
xlsx/<年度>-<団体コード>.xlsx
   └─ tools/oracle/gen-golden.mjs（HyperFormula で計算）
        └─ app/tests/golden/<団体コード>-<年度>.json（入力と期待値）
             └─ app/tests/golden.test.ts（エンジンの結果と全件比較）
```

- **ゴールデン**: ランダムな入力と境界値（軽減の基準額ちょうど・±1円、限度額付近、年齢の切り替わり、控除の区間の境目、世帯員の人数など）。高崎市 令和8年度は938件が一致。
- **公式の計算例**: 市のページの3人世帯の例（合計401,700円）を再現する（`app/tests/example.test.ts`）。
- **画面**: 計算例を入力して金額が表示されること、ヘルプの開閉、フォームの値の変換（`app/tests/TaxPage.test.tsx`）。
- **LibreOffice との突き合わせ**（`tools/oracle/compare.mjs`）: HyperFormula の計算が Excel と同じかを確かめる。遅いので、自治体の追加時と年度の更新時だけ実行する。
- ゴールデンには、使ったExcelのファイル名と SHA-256 を記録する。

公開（`published`）の条件: ゴールデンが全件一致すること、公式の計算例があれば一致すること、人が確認したこと（`reviewer` と `verifiedAt`）。

## 9. 画面

- 旧サイトのCSS（`app/public/common/`）は `data-item` / `data-item-val` 属性で値を表示する。React でも同じ属性を出力して、CSSを変えずに済ませている。
- 旧CSSの `body > .wrap` の余白は、`#root` の中に描画するため `app/src/styles/app.css` で `#root > .wrap` にも付けている。
- 資産割がある自治体（ルールセットのどれかの区分で `assetRate > 0`）だけ、固定資産税額の入力欄と内訳の「資産割額」を出す。
- ルールセットの `meta.caveats` / `meta.notes` を、ページ上部の「〇〇の計算についてのご注意」に出す。「ご注意」の末尾には `meta.sources` を出典として並べる。
- 世帯員は配列の state で持ち、`.map()` で描画する（旧版の DOM の複製はやめた）。
- 入力値が変わるたびに再計算する（`useTaxCalculation` は `calculate` を `useMemo` で呼ぶだけ）。

## 10. ビルドと配置

- Vite で静的ファイル（HTML/JS/CSS）にビルドする。`app/` 直下の `*.html` がすべて入口になる（自治体ごとのページ。13章）。`base: './'` なので、どのパスに置いても動く。
- ルールセットは自治体・年度ごとに別のチャンクになり、必要な1件だけを読み込む（自治体が増えても初回の読み込みは増えない）。
- 広告枠を置く場合は高さを固定し、レイアウトがずれないようにする。税額の数字のすぐ近くには置かない。

## 11. 自治体・年度を追加する手順

1. 市のExcel・税率表・計算例を公式サイトから取得する。Excelは `xlsx/<年度>-<団体コード>.xlsx` に置く。
2. ルールセットJSONを `status: "draft"` で作る。出典の URL と取得日を `meta.sources` に書く。
3. Excelの数式を読み、データで表せない計算がないかを確認する。あればエンジンに部品を足す（4章）。
4. `tools/oracle/` でゴールデンを作り、全件一致するまで直す。公式の計算例があればテストに加える。
5. 人が確認し、`status` を `reviewed`（または `published`）にして、`verifiedAt` と `reviewer` を入れる。

年度の更新では、新しいExcelでゴールデンを作り直し、税率・軽減の基準額・控除表の差分を確認する。

## 12. 対応していないもの・未決事項

- 給与収入850万円超の所得金額調整控除（警告を出すだけ）。
- 特定同一世帯所属者の軽減判定、条例による減免（市のExcelも非対応）。
- 1人が加入 → 脱退 → 再加入する、途中が抜けた期間（市のExcelも非対応）。
- 加入月・脱退月の入力欄（エンジンとExcelとの照合は済み。画面は未対応）。
- 平等割の 1/2・1/4 軽減の、高崎市での根拠資料の確認。
- 入力を「年齢＋所得」だけで済ませる簡易モードを用意するか（未就学・18歳未満の境目で誤差が出うる）。

## 13. 群馬県の市町村への展開

依頼: `requests/20261111-群馬県中の市町村の対応の件.md`。結果は [docs/gunma/report-2026.md](../docs/gunma/report-2026.md)。

### データの流れ

```
群馬県「市町村別国民健康保険税率」PDF ─┐
市町村の税率ページ・計算例              ├─(人が転記)→ tools/gunma/master-2026.json（マスター）
                                         │                ├─ gen-rulesets.mjs → app/src/data/rulesets/2026/<コード>.json
                                         │                └─ gen-pages.mjs    → app/<slug>.html, app/src/data/municipalities.ts
市町村のExcel（xlsx/）──── gen-golden.mjs（LibreOffice: lo_eval.py）→ app/tests/golden/<コード>-2026.json
```

- **マスター**が自治体ごとの値の唯一の入力。ルールセットとページは生成物なので手で直さず、マスターを直して生成し直す。
  高崎市のルールセット（`102024.json`）は人が確認済みのため、`gen-rulesets.mjs` は上書きしない。
- 税率・限度額以外（所得の控除表、軽減判定、年齢区分）は国の基準なので、高崎市のルールセットを雛形にする。
- 限度額を月ごとに判定するときの丸め（`capMonthlyRounding`）は、高崎市以外は `floor` にした（通年加入では結果に影響しない）。

### ページ

- 高崎市は `index.html`（既存のURLを変えない）。ほかは `<ローマ字>.html`（例: `maebashi.html`）。どのページも同じアプリで、`<div id="root" data-municipality="団体コード">` で自治体を決める。
- ページはすべて `index.html` から生成する（タイトル・説明・団体コードだけ差し替え）。`index.html` の見た目を直したら `gen-pages.mjs` を実行する。
- メニュー（ドロワー）に群馬県35市町村のリンクを出す（既存CSSの `nav-drawer__*` を使う）。
- ルールセットは自治体ごとに別チャンクのまま。ページを開くと、その自治体の1件だけを読み込む。

### 注意書き（`meta.caveats`）

市町村の資料で確認できなかった値は、補った方法を注意書きで示す。文言は `components/Notices.tsx` の `CAVEAT_TEXT`。

| コード | 意味 | 付ける条件（`gen-rulesets.mjs`） |
|---|---|---|
| `RATES_FROM_PREF_ONLY` | 税率は県の資料だけが根拠 | マスターの `official` が `yes` 以外 |
| `CHILD_SUPPORT_NOT_CONFIRMED` | 子ども・子育て支援金分を市町村の資料で確認できていない | `official` が `no` |
| `CAPS_ASSUMED` | 課税限度額は国の基準額と仮定 | `capsSource` が `official` / `excel` 以外 |
| `RULES_ASSUMED` | 軽減判定・端数処理などは国の基準と高崎市の方法 | Excelでの照合も、公式の計算例の再現もない |
| `NOT_VERIFIED_WITH_EXCEL` | 市町村の試算表で照合していない | Excelでの照合がない |
| `MUNICIPAL_EXCEL_DIFFERS` | 市町村の試算表と結果が違うことがある（理由は `notes`） | 照合でExcel側の問題が見つかった |

### 市町村のExcelとの照合

- Excelは自治体ごとに入力欄の位置も対応範囲も違うため、`gen-golden.mjs` に自治体ごとの入出力セルの対応（アダプタ）を書く。
- 計算は LibreOffice で行う（HyperFormula は関数の対応が足りないExcelがあるため）。`lo_eval.py` はブックの日付基準（1900年/1904年起算）に合わせて日付を入れる。
  読み取り専用で開くとセルを空にする操作が効かないので、通常で開いて保存しない。
- Excelの対応範囲（軽減の有無、未就学児の軽減の有無、給与と年金の併用控除の有無）はアダプタの `dom` に書き、その範囲のケースだけで比べる。
- Excel側に誤りや古い値があるときは `app/tests/golden/excel-diffs.json` に理由と「Excelの条件」（限度額、控除表、軽減の基準額など）を書く。
  テストは、Excelの条件で計算したエンジンの結果がExcelと一致することを確かめる。理由を書くだけでは通らない。
